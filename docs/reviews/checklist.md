# Review checklist

Use for every change (skill `code-review`). Severity: **blocking** (must fix before merge), **major** (fix or
justify in the record), **minor** (optional).

## Correctness
- [ ] The change does what its requirement rows say; edge cases (empty input, missing tables, NULLs, mixed-case and
      reserved identifiers, several schemas) are handled.
- [ ] Error messages tell the user or agent how to fix the input.
- [ ] No behavior change hidden in a refactoring.

## Safety and privacy (blocking when violated)
- [ ] Every SQL from users, LLMs, YAML or agents passes `check_readonly` and runs through `run_select` with a time
      limit; identifiers are quoted with the dialect preparer, values are never concatenated into SQL.
- [ ] Values of sensitive columns are never stored, logged, embedded or sent to an LLM.
- [ ] No secrets or credentials in code, config, tests, docs or evidence; URLs rendered without passwords.
- [ ] MCP tools validate and bound their inputs (row caps, timeouts, sizes).

## Portability
- [ ] Works on SQLite, DuckDB, PostgreSQL, MySQL/MariaDB and SQL Server, or the limitation is documented.
- [ ] Dialect branches are covered by the cross-engine scenario; cross-engine run done for SQL/dialect changes.

## Quality
- [ ] Types are precise; no new `Any` where a real type exists; no `# type: ignore`.
- [ ] Tests assert behavior, carry `req` markers, and would fail without the change.
- [ ] New dependencies are optional extras and have an ADR.

## Retrieval and knowledge
- [ ] Eval numbers before and after for retrieval-affecting changes (BM25 and the KB's embedder); no gate lowered.
- [ ] Knowledge-graph changes keep all relations verified; `kb/` derived files regenerated by `sqlmem build`.

## Documentation and evidence
- [ ] README (users), `docs/` (design), CHANGELOG updated; ADR for significant decisions.
- [ ] Fresh `scripts/verify.py` evidence for the reviewed commit; claims in the PR match it.
- [ ] Gaps (engines not run, skipped tests) are stated.
